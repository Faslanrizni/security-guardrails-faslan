# AI Code Detection

Detects AI-generated code committed to the repository using heuristic analysis
of commit messages and file content.

## How it works

The detector scores each commit on a 0–1 scale using multiple signals:

| Signal | Weight | Notes |
|---|---|---|
| Explicit AI signature comment | +0.50 | "Generated by Copilot / ChatGPT / Claude…" |
| AI tool mention in commit message | +0.50 | "via Copilot", "AI-assisted", etc. |
| Verbose explanatory comments | +0.08–0.15 | "This function does / is used to…" |
| TODO-stub patterns | +0.10 | `raise NotImplementedError`, etc. |
| Placeholder names | +0.10–0.15 | `foo`, `bar`, `MyClass`, `myFunction` |
| High comment density (>45%) | +0.20 | |
| Many docstring blocks | +0.10 | >6 docstring delimiters |
| Repetitive line patterns | +0.15 | Same line appears >8 times |
| High function/class density | +0.15 | >1.5 units per 10 lines |
| High character entropy (>4.8) | +0.10 | |
| Long commit message (>60 words) | +0.20 | |
| Bullet/numbered structure in message | +0.15 | |
| Human frustration signals | −0.05–0.10 | "wtf", "hack", "workaround", etc. |

### Confidence bands

| Score | Label | Action |
|---|---|---|
| 0.00 – 0.39 | Clean | No action |
| 0.40 – 0.69 | Possible AI | Flagged in PR comment |
| 0.70 – 1.00 | Likely AI | Merge blocked until reviewed |

## Usage

```bash
# Basic scan
python tools/ai-detection/ai-code-detector.py

# Block on high-confidence findings
python tools/ai-detection/ai-code-detector.py --block

# JSON output (for CI integrations)
python tools/ai-detection/ai-code-detector.py --json --block

# Scan a specific commit
python tools/ai-detection/ai-code-detector.py --commit abc1234 --block

# Verbose debug output
python tools/ai-detection/ai-code-detector.py --verbose
```

## CI integration

The detector is called automatically by both CI systems via the shared templates:

**GitHub Actions** — `ci/github/ai-detection.yml`  
Integrated into `ci/github/security-orchestrator.yml` as the final step.

**Azure DevOps** — `ci/azure-devops/ai-detection.yml`  
Integrated into `ci/azure-devops/security-orchestrator.yml` as the final step.

Detection results are uploaded as a pipeline artifact (`ai-detection-results`)
and posted as a PR comment (GitHub only) for developer visibility.

## Policy

Enforcement is governed by `policies/ai-code.yaml`.  
The block rule is registered in `enforcement/blocking-rules.yaml` as `ai_code_requires_review`.

## Reducing false positives

- Add human signals to `HUMAN_SIGNALS` in the detector source.
- Lower `thresholds.block` in `policies/ai-code.yaml` to tighten blocking.
- Add paths to `scan.exclude_paths` to skip generated/vendor directories.
